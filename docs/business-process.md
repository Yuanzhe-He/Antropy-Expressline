# 业务流程与口径

## 1. 产品边界

系统当前按三个模块拆分：

- `换单`
- `清关`
- `陆运`

其中本期已实现的业务口径：

- `换单` 可单独报价
- `清关` 可单独报价
- 某些票会同时有 `换单 + 清关`
- 当一票业务同时包含 `换单 + 清关` 时，系统将其视为连续业务
- `落柜` 被纳入 `清关` 模块
- `码头费` 也被纳入 `清关` 同页计算，不再单独拆一个前台页面

## 2. 换单模块

### 前台输入

- 船公司
- 业务性质
- 提单数，默认 `1`
- 混装柜型与数量
- demoras 天数
- 汇总币种
- 税前 / 税后显示
- 各费用项税率覆盖

### 前台输出

- 计算公式
- 解释
- `cargos locales`
- `garantia`
- `demoras`
- 总数
- 是否只能给客户 / 收货人开发票
- `corte de demoras` 谁能做

### 后台维护

- 船公司表
- 每家船公司的柜型
- `cargos locales`
  - 后台可新增费用名目，并维护名称、税率、BL 金额和柜型金额
- `garantia`
- `demoras`
- 发票规则
- `corte de demoras`
- 默认税率
- demoras 阶梯支持在后台新增 / 删除

## 3. 清关模块

### 总体逻辑

清关模块是一个一页式流程，包含：

- 码头固定费
- 码头堆存费
- 落柜
- 清关堆场费

### 前台输入

- 业务性质
- 港口
- 码头
- 船公司
- 场站
- 混装柜型与数量
- 天数
- 汇总币种
- 税前 / 税后显示
- 各费用项税率覆盖

### 前台输出

- 各费用项公式
- 各费用项解释
- 各费用项税前 / 税后金额
- 总数
- 当前选择的港口 / 码头 / 场站

### 后台维护

- 船公司与场站映射
- 港口
- 码头
- 场站
- 码头固定费
- 码头堆存费阶梯
- 落柜费
- 清关堆场费
- 默认税率
- 币种
- 码头堆存阶梯支持在后台新增 / 删除

## 4. 场站与船公司关系

### 业务口径

- 场站取决于 `港口 + 船公司`
- 一个港口下可以有多个码头
- 一个场站可以关联多个港口
- 一个场站可以关联多个船公司
- 一个 `港口 + 船公司` 组合也可能对应多个场站

### 当前实现

- 前台先选 `港口 + 船公司`
- 系统自动筛出可用场站列表
- 前台再选择具体场站
- 后台同时维护：
  - 船公司视角的场站映射
  - 场站视角的船公司映射

保存时系统会把两边映射合并，避免只维护一边。

## 5. 费用计算规则

### 5.1 固定费用

固定费用按“柜”计算。

例如：

- `20GP x 3`
- `40HQ x 2`

系统会分别读取各柜型单价，再乘数量后汇总。

### 5.2 可变费用 / 堆存费

堆存费是按天、按阶梯、按箱型累进计算。

示例：

- `0-7 天：0`
- `8-10 天：115`
- `11-30 天：200`

如果输入 `20 天`，则系统会按各区间逐段累计，而不是只取最后命中的一个区间。

### 5.3 免费天

免费天不单独做一个字段，而是通过：

- 区间金额 = `0`

来表示。

### 5.4 Demoras 的柜型与尺寸分配

Demoras 规则集可以按「费用组 + 柜尺寸」拆分。系统不需要新增数据库字段来表达这一层：每家船公司的 `demurrage.ruleSets[]` 保存多套阶梯，`assignmentsByContainerType` 把 20 个具体柜型 key（例如 `20GP`、`40HC`、`20FR`、`40RF`）显式指向某个规则集。

因此同一费用组如果 20 尺与 40 尺金额不同，必须拆成不同 rule set，而不能把 Excel 中相同天数段的 20"/40" 行录成一个连续阶梯。报价端按用户选择的具体柜型 key 取对应 set，免费天仍由该 set 内的 0 金额阶梯表达。

### 5.5 本地费用名目

`cargos locales` 可以按船公司新增费用名目。新增名目不是新的业务流程，而是和原有本地费用逐项相加。

例如：

- `Service Fee`
- `Electronic Data Interchange`
- `Delivery Order Fee`
- 新增的 `Documentation Handling Fee`

系统会把这些本地费用一起纳入 `cargos locales` 小计，再进入换单总价。

### 5.6 本地费用的柜尺寸分价（尺寸列）

本地费用的列由每条船公司自己的 `containerGroups`（列 key + 显示 label）定义，报价按柜型的候选 key 顺序 first-match 取价。2026-07 起系统支持按柜尺寸分价，一条线的列结构在两种形态里**二选一（合并列 xor 尺寸列）**：

- **合并列**：一列覆盖 20/40 同价。key 例：`gp-hq-dc`、`ot-fr-rf`、`gp-hq-dc-20-40`。活形态：**ONE**（干货用 `gp-hq-dc-20-40` 合并列，特种柜用 `ot-20/ot-40/fr-20/fr-40/rf-20/rf-40` 逐族尺寸列）。
- **尺寸列**：同族 20/40 不同价时整线拆为尺寸列。key 例：`gp-hq-dc-20`、`gp-hq-dc-40`、`ot-fr-rf-20`、`ot-fr-rf-40`。活形态：**ZIM**（2026-07-11 起 4 列：GP HQ DC 20'/40'、OT FR RF 20'/40'；Import Cont Management Fee 20'=20 USD / 40'=40 USD，其余项 20/40 同价填两列）。

尺寸归属由柜型 key 前缀决定：`2x` 走 20 尺列，`4x`（含 45 尺）走 40 尺列。列的显示名来自数据里的 `label`，不需要改代码或翻译。

**录入 SOP（必须遵守）：**

1. 自定义柜型 key 必须带尺寸前缀（20/40/45 开头）；没有前缀的自定义柜型只会解析合并列，在纯尺寸列的线（如 ZIM）上会落到兜底价。
2. 尺寸列启用后**不要清空任何单元格**：清空后该柜型无命中，会静默按该费用的第一个列价计费（兜底首键由存储键序决定——键越短越靠前，不受录入顺序控制）。
3. 不要给费用的列集合引入比现有更短的 key：这会无声改变所有无命中柜型的兜底目标。
4. 自建非标准柜型在尺寸列线上**滞期费会静默为 0**（滞期分配推导只覆盖 20 个标准柜型），必须在 admin 里为它手工指定 demurrage 规则集分配。

## 6. 天数口径

### 行业资料

根据官方资料，行业里并不存在一个跨所有港口、所有码头、所有船公司的统一“第 0 天 / 第 1 天”口径，实际起算点经常由承运人或具体 terminal tariff 决定。

参考：

- FMC：`demurrage accrues when a container exceeds free time on a marine terminal`
  - https://www.fmc.gov/detention-and-demurrage/
- FMC 审计最佳实践：货物可提状态日期不应简单等于船到港日期，除非货物当天实际可提
  - https://www.fmc.gov/databases-and-publications/vessel-operating-common-carrier-vocc-audit-program/
- Maersk 美国进口信息：free time 的起算点随 terminal 而异，常见写法是“集装箱卸船后的下一个业务时点开始”
  - https://www.maersk.com/zh-cn/local-information/north-america/united-states-of-america/import
- Maersk 条款：Demurrage 针对的是 free time 之外，货柜仍留在 terminal / port / depot 内的时间
  - https://terms.maersk.com/dnd

### 系统实现口径

为了防错和便于录入，当前系统采用下面的产品口径：

- 前台允许从 `0` 天开始输入
- 后台阶梯按顺序维护
- 免费段可以显示为 `0-7`
- 系统会自动顺延下一段的起始日
- 后台用户只需要维护：
  - 当前段的结束日
  - 金额
  - 币种
  - 税率

这样做的目的不是宣称行业统一从 `0` 计费，而是为了：

- 避免区间重叠
- 避免人工把 `6-8`、`8-10` 这种规则输错
- 让演示和报价操作更稳定

## 7. 税率与汇率

### 汇率

- 当前仅支持 `USD / MXN`
- 不同费用项可有不同币种
- 汇总时统一换算到前台选择的汇总币种

### 税率

- 后台给每项费用配置默认税率
- 前台可以临时覆盖税率
- 当前税率预设默认包含：
  - `0%`
  - `16%`

## 8. 连续业务

### 定义

业务性质包含：

- `仅换单`
- `仅清关`
- `换单 + 清关连续业务`

### 当前实现

如果前台在换单页选择：

- `换单 + 清关连续业务`

那么换单计算后，系统会把以下上下文带到清关页：

- 船公司
- 柜型
- 数量
- 汇总币种
- 税前 / 税后显示

这让同一票业务可以连续处理，而不需要再次全部录入。

## 9. 当前已确认但尚未完全产品化的点

- 清关堆存阶梯当前可编辑现有行，但还没有可视化新增 / 删除阶梯行
- 数据持久化仍是 JSON 文件
- 账号权限目前暂时关闭，所有访问者都可进入前台和后台修改规则
