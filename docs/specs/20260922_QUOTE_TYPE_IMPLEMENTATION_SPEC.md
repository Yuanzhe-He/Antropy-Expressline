# Single-shipment quotation and long-term rate card

Source: Chandler's 2026-09-22 explicit request and screenshot. A long-term quote lists prices per one unit for alternative specifications; a single-shipment quote prices actual ordered quantities. This is independent of cargoType (FCL/LCL/BBK/AIR) and geography quoteMode. Implement, test, push, release and verify live in the previously authorized isolated clone. No external Bill message sent; deliver updated draft only. Original Cursor repo remains read-only.

## Contracts

- `header.quoteType`: `single` (legacy/default) or `long_term`. `settings.headerDefaults.quoteType` controls fresh quotes only. Existing drafts missing the field stay single.
- Keep existing `lineItems`, `cargoPricing`, `cargoPricingByType` for single mode, including inactive-mode edits. They never become long-term prices or lose quantities on a switch.
- `header.rateCardsByType`: map keyed FCL/LCL/BBK/AIR. Each card is `{variants:[{id,label}],rows:[{id,category,code,conceptEn,conceptZh,conceptEs,section,chargeKind,included,unitOfMeasure,currency,remark,cells:{[variantId]:{unitPrice,unitPriceMax,isAtCost}}}]}`. Quantity is an invariant1, not an editable stored purchase count. Each row has one currency and UOM, applicable to its variant prices. Blank cell is unknown/not offered, distinct from0; AT COST and ranges remain explicit. Rows are scoped by card type and quote geography.
- `settings.rateCardDefaults`: same map, reusable backend presets. Explicit empty row arrays remain empty. Defaults are copied only into newly initialized cards; stored drafts are snapshots and are not overwritten by later admin edits.
- Hidden POST fields: `rateCardsByType` JSON on quote, `rateCardDefaults` JSON plus `rateCardDefaultsPresent=1` on admin. New shared UMD `public/quote-rate-card.js` exports `normalizeQuoteType(value)`, `normalizeRateCard(value)`, `normalizeRateCardsByType(value)`, `parseRateCardsByType(raw)`, `createDefaultRateCard(cargoType,feeTemplates)`, `validateRateCard(card,{forExport:false})`, `validateRateCardsByType(map)`, `buildRateCardView(card,quoteMode)`; shared editor uses these functions. Parser/normalizers preserve invalid-state errors rather than silently dropping bad input. Limits:12variants,100rows percard,4cargo types,1MiB JSON; safe IDs and unique labels, nonnegative finite prices, max>=min, USD/MXN currency; no prototype keys. Export requires a valid cargo selection and at least one offered cell in included active rows. Blank prices permitted in draft/configuration. Errors must be visible, no partial admin writes.
- Default FCL columns:20GP/40GP/40HQ. Other cargo types:one editable “标准规格” column. Default rows copy only enabled/applicable fee metadata from admin library; all variant prices start blank. Never copy a screenshot40HQ price into all variants. Users can add/delete/rename columns and rows; explicit column/row delete is the only removal action.
- `buildRateCardView` returns `{variants,rows,chargeSections,errors}` with fixed and contingent groups using existing section/group conventions where practical; no totals, no cargo autocharges. Root can adapt grouping for PDF. The view exposes `quoteType`, `rateCard` and forces `showTotals=false` for long_term. Single paths retain existing behavior.
- Long-term UI has a visible Qty1 column/read-only indicator, per-variant cells, fee metadata editing, add/remove row and variant controls, fixed vs contingent classification. Hide/disable single-only pricing/fee/subtotal controls while preserving their state. Shared editor also drives admin presets with an independent cargo selection. No hidden input constraint can block a valid different mode.
- PDF labels quoteType and prints long-term matrix with Qty1, UOM, row currency and remarks. Blank cells render dash, never0. No cross-variant sum, subtotal, FX total, dual-currency VAT or generated cargo charge regardless of stale/tampered flags. Internal code is second column; customer hides it. Group wide matrices into at most3specifications per panel/page, repeating row descriptors; use landscape if needed for readability. Single PDF stays portrait/unchanged except explicit type label.
